# Деплой OQU в продакшен

Платформа хранит загруженные видео на диске, поэтому нужен сервер с **постоянной
файловой системой** — VPS (например PS.KZ, Hetzner, DigitalOcean), а не Vercel.
Всё разворачивается одной командой через Docker Compose: приложение + Postgres.

## Что понадобится

- VPS с Docker и Docker Compose (Ubuntu 22.04+).
- Домен, направленный на IP сервера (для HTTPS).
- 10 минут.

## Шаги

### 1. Скопировать проект на сервер

```bash
git clone https://github.com/flyordie013/Sagatovai.com.git oqu && cd oqu
```

### 2. Заполнить настройки

```bash
cp .env.production.example .env
nano .env
```

Обязательно заполнить:

- `AUTH_SECRET` — сгенерировать: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`
- `POSTGRES_PASSWORD` — придумать надёжный пароль для базы.
- `APP_URL` — публичный адрес сайта, например `https://oqu.kz`.
- `BOOTSTRAP_OWNER_EMAIL` и `BOOTSTRAP_OWNER_PASSWORD` — ваш аккаунт владельца
  (создаётся автоматически при первом запуске).

По желанию: `GROQ_API_KEY` (бесплатный ключ включает AI-наставника),
`RESEND_API_KEY` + `EMAIL_FROM` (письма для сброса пароля).

### 3. Запустить

```bash
docker compose up -d --build
```

При старте контейнер сам:

1. применит миграции базы,
2. создаст аккаунт владельца из `BOOTSTRAP_OWNER_*`,
3. поднимет приложение на порту `3000` **только на localhost сервера**.

Проверить: `curl http://127.0.0.1:3000/api/health` → `{"ok":true}`.

### 4. HTTPS

Поставьте перед приложением обратный прокси с автоматическим сертификатом.
Проще всего — Caddy:

```
# /etc/caddy/Caddyfile
oqu.kz {
    reverse_proxy localhost:3000
}
```

```bash
docker run -d --network host -v /etc/caddy/Caddyfile:/etc/caddy/Caddyfile \
  -v caddy_data:/data caddy:2
```

Готово — сайт доступен по `https://oqu.kz`.

### 5. Проверить, что порт 3000 закрыт снаружи

Приложение слушает только `127.0.0.1`, весь трафик обязан идти через HTTPS.
Если порт 3000 доступен снаружи, пароли уходят открытым текстом, а заголовок
`X-Forwarded-For` можно подделать и обойти защиту от перебора.

```bash
# на сервере — должно отвечать {"ok":true}
curl -s http://127.0.0.1:3000/api/health

# с ЛЮБОЙ другой машины (свой ноутбук) — должно быть отказано в соединении
curl -m 5 http://IP_СЕРВЕРА:3000/api/health
```

Второй запрос обязан завершиться ошибкой (`Connection refused` или таймаут).
Если он вернул `{"ok":true}` — порт опубликован наружу: проверьте, что в
`docker-compose.yml` в сервисе `app` строка портов начинается с `127.0.0.1:`,
и перезапустите `docker compose up -d`.

## После запуска

Войдите под аккаунтом владельца → `/admin`:

1. Создайте курсы, модули и уроки.
2. Загрузите видео к урокам (кнопка «Загрузить видео»).
3. Первые 1–2 урока платных курсов отметьте галочкой «Бесплатный урок».
4. В разделе «Геймификация» добавьте цели, достижения и награды.
5. Опубликуйте курсы.

## Эксплуатация

```bash
docker compose logs -f app      # логи
docker compose pull && docker compose up -d --build   # обновление
docker compose down             # остановить
```

**Бэкап базы** (настройте по cron):

```bash
docker compose exec db pg_dump -U oqu oqu > backup-$(date +%F).sql
```

Загруженные видео лежат в Docker-томе `videos` — включите его в резервное
копирование сервера.

## Заметки

- Миграции применяются автоматически при старте. Чтобы отключить и запускать
  вручную (`pnpm db:migrate`), задайте `RUN_MIGRATIONS=false`.
- Приложение **откажется стартовать без `DATABASE_URL`** в продакшене — это
  защита от случайного запуска на встроенной dev-базе (данные бы стирались).
- Для масштабирования на несколько инстансов понадобится вынести rate-limit в
  Redis (сейчас он в памяти процесса) — для одного VPS это не требуется.
