# Повторная проверка: мобильная версия, видео, материалы

## Исправления

- Лимит материалов по умолчанию 200 МиБ (209715200 байт), включая compose и оба шаблона окружения. Фактический поток ограничен на сервере, файлы вне public, проверка доступа при каждом запросе.
- Докачка материалов: одиночные Range, суффиксы, открытые диапазоны, ETag / If-Range, 416 для недопустимых диапазонов. HEAD не передаёт тело. Прерывание скачивания не требует начинать заново в клиентах, поддерживающих докачку.
- Загрузки материалов и видео допускают до 30 минут, показывают ошибки и повтор. Очередь останавливается при размонтировании; активный запрос отменяется. Переход по ссылке и закрытие вкладки предупреждают о загрузке/несохранённых изменениях.
- Docker запускает standalone-сервер с scripts/http-timeouts.mjs: серверный requestTimeout тоже 30 минут вместо стандартных пяти; headersTimeout остаётся 60 секунд. Изменения только клиентского XHR timeout было бы недостаточно.
- Видео прикрепляется под блокировкой записи урока: параллельная замена очищает предыдущий файл, удаление урока во время загрузки очищает новый. Удаление уроков, модулей и курсов собирает актуальные файлы внутри транзакции. Открытый поток видео удерживает файловый дескриптор при замене.
- Мобильный плеер: кнопки 44 px, отдельная строка времени/скорости, системный select, панель под видео на узких экранах. В полноэкранном режиме панель остаётся поверх видео. Клавиши вложенных кнопок и select не перехватываются плеером.
- Меню прокручивается в коротком окне; переход к desktop закрывает его и снимает блокировку прокрутки. Фокус остаётся внутри открытого меню.
- Несохранённые правки, введённые во время сохранения формы, остаются отмеченными. Несколько форм не вызывают несколько подтверждений ухода подряд. Ошибки смены/сброса пароля сохраняют введённые значения.
- Завершение урока, миссии, достижения и XP записываются одной транзакцией с блокировкой профиля. Обратное начисление достижений использует тот же порядок блокировок и учитывает незавершённые записи.
- Параллельные заявки не дублируются; выдача доступа согласована с заявкой и удалением курса. Оплата и доступ остаются одной транзакцией.
- Ссылка сброса пароля используется однократно даже при одновременных запросах. Тексты писем, ссылки сброса и временные пароли не пишутся в журнал при отключённом SMTP.

## Проверки

Изолированная PostgreSQL 16 на localhost:55432; только тестовые данные.

1. `scripts/qa-release.ts` — 62 HTTP/DB-проверки при MAX_MATERIAL_MB=1: роли, отзыв доступа/сессии, форматы, сигнатуры, лимиты, повтор загрузки, замена/удаление/порядок, Range, сохранение позиции и свободный порядок уроков.
2. `scripts/qa-media.ts` — 28 проверок при MAX_MATERIAL_MB=200: настоящий поток 200 МиБ, SHA-256 полного скачивания и двух частей докачки; 201 МиБ отклоняется и очищается; пять параллельных замен видео; удаление урока во время загрузки; авторизация Range/ETag/HEAD и очистка файлов.
3. Chromium: ширины 320, 360, 390, 768, 1024, 1280, 1536; управление плеером клавиатурой, скорость, воспроизведение, пауза, восстановление позиции.
4. WebKit с эмуляцией iPhone: скачивание с русским именем, перемотка, скорость, повтор загрузки после искусственного сетевого сбоя; меню 844×390 и переход в desktop; формы и редактор материалов 320–1280 px. Лендинг, каталог, курс, кабинет, профиль и разделы админки при 390 px без горизонтального переполнения.
5. Две вкладки: два разных завершённых урока дали ровно 50 XP; две заявки дали одну запись; две выдачи доступа сохранили одну оплату; два сброса по одному токену изменили session_version один раз.
6. Удаление через админку: оплаченный курс архивируется с сохранением платежа; неоплаченный удаляется с материалами.
7. `pnpm lint`, `pnpm typecheck`, `pnpm build`.

Повторение HTTP-проверок описано в UX_RELEASE_QA.md. После первого скрипта перезапустить тот же локальный сервер с MAX_MATERIAL_MB=200 и выполнить `OQU_RELEASE_QA=local pnpm exec tsx scripts/qa-media.ts`. Для видео нужен локальный тестовый H.264 MP4 по пути output/playwright/qa-video.mp4. Артефакты и cookie не коммитятся и не включаются в образ.

## Эксплуатация и границы проверки

- Изменения не требуют миграции или очистки рабочей БД. Перед выкладкой scripts/update.sh создаёт и проверяет резервную копию; старый образ сохраняется для отката.
- На VPS обнаружен MAX_MATERIAL_MB=50: при выкладке требуется явно заменить на 200 в /root/oqu/.env, одного изменения значения по умолчанию недостаточно.
- SMTP на VPS не настроен. Восстановление почтой показывает сообщение с переходом в поддержку вместо обещания неотправленного письма. Включение требует SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASSWORD, EMAIL_FROM; отправка и доставка писем этим аудитом не подтверждены.
- WebKit-эмуляция не заменяет физический iPhone: нативный iOS fullscreen, сворачивание Safari и длительная загрузка по мобильной сети требуют проверки на устройстве. Докачка зависит от поддержки браузера/менеджера загрузок.
